Week 2

Making something move

Flexbox where you actually need it, GSAP linked and running, and your first two scroll-driven effects on your own page. Everyone leaves today having made something move.

Last week you built a page and put it on the internet. Today you make it behave.

This is the week the module stops being a refresher. By the end of the session your own page will fade its chapters in as the reader arrives at them, and hold a scene still while text passes over it — the two effects that most of the scrollytelling canon is built from.

We get there by way of a Flexbox recap, because a scene that falls apart when the window resizes will only look worse once it moves. Layout first, then behaviour. That order matters more than it sounds.

Part one

Layout before behaviour

Open demos/01-flexbox.html. It shows the same chapter markup twice: once as plain block elements, once with Flexbox. Identical HTML, one extra class.

You met Flexbox last year. The recap is here because scrollytelling scenes are the case where it earns its keep: a chapter is almost always some text beside a picture, and it has to survive being 1400 pixels wide on the studio monitor and 390 on a phone.

css/style.css

.chapter--flex {
  display: flex;        /* children sit in a row               */
  flex-wrap: wrap;      /* ...and drop to a new line when tight */
  gap: 2rem;            /* space between them                   */
  align-items: center;  /* line them up vertically              */
}

.chapter--flex .chapter__text   { flex: 1 1 20rem; }
.chapter--flex .chapter__figure { flex: 1 1 24rem; }

The line worth understanding is flex: 1 1 20rem. It is three values at once: may grow, may shrink, aim for 20rem. That third number is what decides when the layout wraps — not a media query. Two children asking for 20rem and 24rem with a 2rem gap need about 46rem of room; below that, they stack. You get responsive behaviour without writing a single breakpoint.

10 minutes · on your own page

Re-level your own chapters

Your starter already has .chapter--figure doing this job with Grid rather than Flexbox — open css/style.css and find it. Either is correct. What matters is that you can read the rule and say what each line does.

  • Find the layout rule for your chapters and read it out loud to the person next to you.
  • Change one value — the gap, the wrap width — and watch what happens.
  • Drag your window from full width to phone width. Nothing should overflow sideways.

Part two · Task 1

Linking GSAP

GSAP is the animation library this module runs on. It is what sits underneath Webflow's interaction tooling, and since 2025 it has been free for commercial use, plugins included. It is the industry-standard tool for this genre, and you are about to use the real one.

Linking it is two script tags. Open demos/02-link-gsap.html and look at the bottom of the file:

index.html — just before </body>

<script src="https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/gsap.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/ScrollTrigger.min.js"></script>
<script src="js/main.js"></script>

Three things to notice. Order matters — the library has to arrive before your code tries to use it, so your own script goes last. ScrollTrigger is separate from GSAP itself; it is a plugin, and it needs GSAP loaded first. And we pin the version to 3.15.0 rather than asking for “latest”, so the code you write today still behaves identically in January when you hand in.

Then, at the top of your own script, one line tells GSAP the plugin exists:

js/main.js

gsap.registerPlugin(ScrollTrigger);

console.log('GSAP', gsap.version, '— main.js connected');

Live Server, not double-click

From today, always open your project through Live Server. A CDN request from a file:// page is unreliable, and you will spend twenty minutes debugging a problem that does not exist. Right-click index.html → Open with Live Server.

Task 1 · 15 minutes · on your own page

Link GSAP and make one thing move

  1. Add the two CDN script tags to your index.html, above your existing js/main.js tag. Remove defer from your own script tag if it is there.
  2. At the top of main.js, add gsap.registerPlugin(ScrollTrigger);
  3. Open the Console (⌥⌘J). You should see the version number print. If you see gsap is not defined, your script order is wrong.

  4. Now make something move. Anything:

    gsap.from('.cover__title', { y: 60, opacity: 0, duration: 1, ease: 'power2.out' });
  5. Reload. Your headline should rise into place.

Commit it

That is a working GSAP install. Commit before you change anything else, so you have a point to come back to.

Part three

The tween vocabulary

A tween is one animation: these properties, over this long, with this easing. Open demos/03-tween-vocabulary.html. There are only four things to learn, and every effect in this module is built from them.

The whole vocabulary. Press R on the demo page to replay.
MethodWhat it doesUse it when
gsap.to() From where it is now, to the values you name. Something leaves, or changes from its resting state.
gsap.from() From the values you name, to where your CSS already puts it. Entrances. This is the one you want most of the time — see below.
gsap.fromTo() You name both ends. Neither end is the CSS state.
stagger One tween, many targets, offset in time. Lists, grids, anything that should arrive in sequence.

Why from() and not to() — this is a marked criterion

The obvious way to fade something in is to set opacity: 0 in your CSS and animate up to 1. Do not do this. If JavaScript fails to load — blocked script, CDN down, a marker with an aggressive network — your reader gets a blank page.

With gsap.from() the finished state is whatever your CSS already says, so the no-JavaScript version of your page is the readable one. The brief requires a no-JavaScript baseline, and this single decision is most of it.

Ease is where the character lives. power2.out starts fast and settles — it feels like something arriving and coming to rest. power2.in does the reverse and feels like something leaving. none is a constant speed and feels mechanical, which is occasionally exactly right. Most of the difference between motion that feels designed and motion that feels like a PowerPoint transition is easing.

Break · 15 minutes

Part four · Task 2

Your first ScrollTrigger

Everything so far has run the moment the page loaded. ScrollTrigger is the piece that ties a tween to the scrollbar. Open demos/04-scroll-fade.html and scroll it slowly.

You will see green and red lines on the right-hand side. Those are markers — development tooling that shows exactly where each trigger starts and ends. They are the single most useful thing about learning this library, and you turn them off before anyone else sees your work.

js/main.js

gsap.utils.toArray('.chapter__text').forEach(function (el) {
  gsap.from(el, {
    opacity: 0,
    y: 40,
    duration: 0.8,
    ease: 'power2.out',
    scrollTrigger: {
      trigger: el,
      start: 'top 80%',
      markers: true          // DELETE BEFORE YOU PUBLISH
    }
  });
});

start: 'top 80%' reads as two positions: the top of the trigger element meets 80% of the way down the viewport. So the animation fires when the element is a fifth of the way up the screen — just after the reader would have noticed it. Change 80% to 50% and it fires much later. This one string is most of your pacing control.

gsap.utils.toArray() grabs every matching element and forEach gives each one its own trigger. Without that loop you would get one trigger watching one element.

Task 2 · 20 minutes · on your own page

Fade your chapters in

  1. Add the block above to your main.js, with markers: true on.
  2. Scroll your page. Watch the markers pass the trigger lines.
  3. Change start to 'top 50%'. Scroll again. Feel the difference in pacing.
  4. Put it back to something you actually like.
  5. Try stagger on a group — your credits list is a good candidate.
  6. Turn markers off. Commit.

If nothing happens

Nine times in ten it is a selector that matches nothing. Type document.querySelectorAll('.chapter__text').length into the Console. If it says 0, your class name is wrong.

Part five · Task 3

Pinning a scene

Open demos/05-pin.html. A picture holds still in the middle of the screen while three captions scroll over it, and the picture changes as each caption arrives. That is the single most recognisable move in the whole genre.

You already had half of this in Week 1

Your starter's scene is pinned by CSS position: sticky alone — no JavaScript involved. Scroll to it now and you will see it hold. What we are adding today is not the pinning; it is knowing which step the reader has reached, so the scene can respond. That is the difference between a picture that sits still and a scene that reacts to the reader — and it is the difference between motion design and interaction design that the brief is asking you for.

js/main.js

gsap.utils.toArray('.step').forEach(function (step, i) {
  ScrollTrigger.create({
    trigger: step,
    start: 'top 65%',
    end: 'bottom 65%',
    onEnter:     function () { showStep(i); },
    onEnterBack: function () { showStep(i); }
  });
});

Note there is no animation in that block at all. ScrollTrigger.create() just watches and calls your function. onEnter fires scrolling down; onEnterBack fires scrolling back up — you need both, or your scene breaks for anyone who scrolls backwards, which is everyone.

Task 3 · 20 minutes · on your own page

Make your scene notice the reader

  1. Add the watcher block to main.js.
  2. Write a showStep(i) function. Start with console.log('step', i) and confirm it fires as you scroll.
  3. Now make it do something visible. Easiest wins: change the figure's caption text, or add a class that highlights the active step.
  4. Scroll back up. Check it still works in reverse.
  5. Commit and sync. Check your live URL updates.

Part six

Reduced motion, done properly

Some people are made genuinely unwell by movement on screen — nausea, vertigo, migraine. The operating system lets them say so, and your page has to listen. Week 1 handled this in CSS. Now that you are animating in JavaScript, you need it there too.

Open demos/07-reduced-motion.html, then turn on System Settings → Accessibility → Display → Reduce motion and reload it.

js/main.js

var mm = gsap.matchMedia();

mm.add('(prefers-reduced-motion: no-preference)', function () {
  // every tween and ScrollTrigger goes in here
});

mm.add('(prefers-reduced-motion: reduce)', function () {
  // deliberately empty — the page is already correct without us
});

gsap.matchMedia() runs the function when the query matches and cleanly reverts everything inside it when it stops matching. No manual teardown, no leftover inline styles stuck at opacity: 0.

This is why gsap.from() mattered earlier. Because your finished state lives in the CSS, “skip the animation” and “show the content” are the same thing. The accessible version costs you nothing except remembering to wrap your code.

Do this now, not in Week 10

Wrap today's two effects in matchMedia before you leave. It takes two minutes now and it is genuinely miserable to retrofit across a finished piece. There is an accessibility review in Week 10 and this is the first thing it looks at.

If you get stuck

gsap is not defined

Your own script is running before GSAP has loaded. Check the order of the script tags — the two CDN tags must come first — and check you have not left defer on your own main.js tag while the CDN tags do not have it.

ScrollTrigger is not defined, but GSAP works

You have loaded gsap.min.js but not ScrollTrigger.min.js. They are two separate files. Check the second script tag, and check gsap.registerPlugin(ScrollTrigger) is in your code.

The animation does not fire at all

Almost always a selector matching nothing. In the Console, run document.querySelectorAll('.your-class').length. If it returns 0, fix the class name. If it returns a number, turn markers: true on and check the trigger lines are where you expect.

Things flash visible, then animate

The page rendered before your script ran. Move your script tag to just before </body> if it is not there already. A small flash on first load is normal on a slow connection and not worth fighting.

The pinned scene jumps or overlaps

Usually a height problem: the sticky element needs a fixed height (100svh) and the steps need enough space between them to scroll through. Check you have not accidentally put overflow: hidden on a parent — that breaks position: sticky silently.

It works locally but not on my live URL

Check the Console on the live page. Usually a path with a capital letter or a leading slash: /js/main.js works locally and fails on GitHub Pages. Use js/main.js.

Something else

Ask in the studio. Out of hours, email a.m.pearson@leedsbeckett.ac.uk with the error text from the Console and your live URL — I normally reply within two working days.
